Data wydarzenia: 14.10.2026. GitHub udostępnił w publicznym podglądzie pliki blokady zależności workflow dla GitHub Actions. Funkcja jest dostępna w planach Free, Team oraz GitHub Enterprise Cloud. Pozwala pozostawić czytelne odwołanie do taga lub gałęzi w workflow, ale uruchamiać dokładny commit zapisany w .github/workflows/actions.lock.

Co rzeczywiście jest blokowane?

Narzędzie gh actions-lock zapisuje commit oraz numery identyfikujące repozytorium akcji. Obejmuje akcje bezpośrednie, ich zależności przechodnie oraz odwołania do workflow wielokrotnego użytku. Jest jednak ważna granica: zależności wewnątrz wywołanego reusable workflow kontroluje plik blokady w repozytorium, w którym ten workflow jest zdefiniowany.

Dlaczego to jest decyzja architektoniczna?

Workflow CI/CD jest częścią łańcucha dostawy. Odwołanie uses: vendor/action@v3 może wskazywać inny kod po przesunięciu taga — bez zmiany w repozytorium korzystającym z akcji. Lockfile przenosi taką zmianę do jawnego diffu. Daje trzy rzeczy: powtarzalność wykonania, spis zależności pipeline’u i punkt kontroli aktualizacji.

Czego lockfile nie gwarantuje?

  • Nie dowodzi, że zablokowany kod jest bezpieczny.
  • Nie zastępuje minimalnych uprawnień GITHUB_TOKEN, ochrony sekretów ani izolacji runnera.
  • Nie blokuje automatycznie obrazów kontenerów, pakietów i skryptów pobieranych przez samą akcję.
  • Nie usuwa obowiązku aktualizacji. Stary, znany commit może zawierać znaną podatność.

Plan pilotażu

  1. Wybierz repozytorium bez krytycznego procesu wydawniczego i zinwentaryzuj uses:, reusable workflows oraz akcje lokalne.
  2. Sprawdź bieżące referencje, wygeneruj lockfile i przejrzyj cały diff. Generator może doprecyzować wersje w samych workflow.
  3. Dodaj w PR kontrolę gh actions-lock --verify. Zmiany pliku blokady skieruj do właściciela bezpieczeństwa pipeline’u.
  4. Skonfiguruj Dependabot dla GitHub Actions i przetestuj aktualizację, cofnięcie oraz przypadek przesuniętego taga.
  5. Dopiero po pilotażu rozważ wymaganie lockfile. Dokumentacja GitHuba ostrzega, że tryb Evaluate polityki jest dostępny tylko w Enterprise.

Interpretacja ArchitectMentor

Największą wartością nie jest kolejny plik YAML. Wartością jest przeniesienie niewidocznej zmiany zależności do miejsca, w którym można ją zobaczyć, ocenić i zatwierdzić. Bez przeglądu diffu lockfile staje się eleganckim sposobem na trwałe uruchamianie czegoś, czego nikt nie przeczytał.
