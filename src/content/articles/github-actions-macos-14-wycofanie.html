Data ogłoszenia: 1 października 2026 r. GitHub zapowiedział wycofanie obrazów runnerów GitHub Actions opartych na macOS 14. To nie jest ciekawostka o numerze systemu. Dla pipeline’u budującego i podpisującego aplikacje jest to termin ważności części środowiska wykonawczego.

Co dokładnie ogłosił GitHub

  • obrazy wskazywane etykietami macos-14, macos-14-large i macos-14-xlarge mają zostać wycofane 2 listopada 2026 r.;
  • GitHub planuje okresy próbnej niedostępności 5, 12, 16, 19, 23, 26, 29 i 30 października;
  • zalecana migracja prowadzi do macos-latest lub runnerów arm64 opartych na macOS 15, zależnie od wymagań zadania;
  • w okresie wycofywania pojemność runnerów macOS 14 może być ograniczana, co może wydłużać czas oczekiwania.

To są fakty z GitHub Changelog z 1 października 2026 r.. Dokładny zestaw narzędzi dla nowych obrazów należy sprawdzić w repozytorium actions/runner-images.

Interpretacja architektoniczna

Najpierw zrób inwentaryzację workflow, reusable workflows i akcji, które wybierają te etykiety pośrednio. Potem uruchom reprezentatywne buildy na docelowym obrazie: kompilację, testy, tworzenie artefaktu, podpisywanie i publikację. Zielony prosty test nie dowodzi, że działa ostatni krok wydania.

Przejście na macos-latest zmniejsza częstotliwość ręcznych migracji, lecz pozwala GitHubowi przesuwać wersję obrazu. To świadomy kompromis, nie darmowy spokój. Jeżeli kompilator, Xcode lub narzędzie podpisujące jest częścią kontrolowanego łańcucha dostaw, przypnij jego wersję jawnie i obserwuj aktualizacje obrazu.

Właściciel pipeline’u powinien mieć datę, test migracyjny i plan odwrotu. Runner to zależność produkcyjna nawet wtedy, gdy nie obsługuje ruchu użytkowników. Bez niego nie ma poprawki, a to zwykle staje się interesujące dopiero w dniu awarii.

Pytanie do projektu: czy potraficie dziś wskazać wszystkie pipeline’y zależne od obrazu macOS 14 i udowodnić, że artefakt z nowego obrazu przechodzi także podpisanie oraz publikację?
