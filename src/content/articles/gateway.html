Gateway API v1.6, wydane 30 czerwca i opisane przez Kubernetes 3 sierpnia, przeniosło zasoby TCPRoute i UDPRoute do kanału Standard w wersji API v1. Pozwala to opisywać kierowanie ruchu warstwy 4 przez port i protokół przy użyciu wspólnego modelu.

Dlaczego to ważne dla architekta?

Jeżeli projekt dotyczy usług korzystających z surowego TCP lub UDP, można ponownie ocenić zależność od rozszerzeń jednego dostawcy kontrolera. Wsparcie konkretnej implementacji i przejście ze starszych definicji trzeba sprawdzić osobno; „standard” nie oznacza, że każda instalacja jest gotowa do zmiany.
